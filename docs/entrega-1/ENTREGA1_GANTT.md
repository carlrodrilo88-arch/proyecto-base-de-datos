# Cronograma Gantt - Proyecto Meditec

## Introduccion

Este cronograma organiza el trabajo del proyecto durante las 12 semanas
establecidas para el curso. La planificacion busca que el equipo avance de forma
ordenada, validando primero el analisis y el diseno conceptual antes de pasar a
la implementacion de la base de datos y la aplicacion web.

El proyecto no se plantea solo como una entrega tecnica, sino como una solucion
para mejorar el trabajo diario de Meditec. Por esa razon, cada fase contempla
revision, documentacion y validacion, con el objetivo de que el sistema final sea
comprensible, defendible y util para las personas que consultaran o generaran
reportes.

## Periodo del proyecto

| Fase | Semanas | Enfoque principal |
| --- | --- | --- |
| Entrega 1 | 1 - 3 | Analisis, propuesta, requerimientos y diseno conceptual |
| Entrega 2 | 4 - 5 | Diseno logico, normalizacion, diccionario, DDL y avance web 30% |
| Entrega 3 | 6 - 8 | Implementacion SQL avanzada, seguridad, pruebas y avance web 70% |
| Entrega 4 | 9 - 12 | Integracion final, manuales, informe y defensa |

## Forma de trabajo del equipo

El equipo revisara cada avance antes de considerarlo final. Las decisiones de
diseno, especialmente las relacionadas con el modelo ER, la normalizacion y la
seguridad, deberan ser comprendidas por todos los integrantes para poder
defenderlas individualmente.

La inteligencia artificial se utilizara como apoyo para analizar, estructurar y
revisar documentos o codigo, pero el grupo sera responsable de validar que cada
resultado tenga sentido para el caso real de Meditec y cumpla los estandares del
curso.

## Notas de control

- Los nombres de responsables deben reemplazarse por los integrantes reales del
  grupo.
- Cada entrega debe cerrarse con su certificacion de calidad y su bitacora IA.
- El tag correspondiente debe crearse solo cuando los archivos hayan sido
  revisados.
- No se debe avanzar con DDL definitivo sin aprobacion del diagrama ER de la
  Entrega 1.
